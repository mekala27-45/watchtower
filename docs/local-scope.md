# Historical initial local candidate scope

This note preserves the initial environment observations on November 1. It is historical evidence, not a description of current implementation or delivery status. Read `reports/verification/delivery.json`, `reports/checklist.json` and `docs/operator.md` for the current state.

The initial execution environment had Node 24.19.0 and bundled SQLite 3.53.3. GitHub CLI had no authenticated host. The package registry DNS probe failed with No such host is known. Required packages were absent from the npm cache and a local inference service was unavailable. Connected Neon and Vercel account listing succeeded, but those listings did not establish direct TLS, free-host eligibility or container deployment. The initial candidate used native JavaScript modules and SQLite to exercise contracts while the TypeScript, pg, eve and hosted Postgres target remained incomplete.

Later verified execution installed the exact locked dependencies, exercised direct TLS Postgres, ran the actual CPU model and completed independent recovery and clean worktree checks. The actual model produced zero supported proposals and failed its useful-model criterion. Its results remain separate from the deterministic baseline. On November 2 the approved Vercel Production credential transfer and container deployment succeeded, followed by three public GET health and origin checks and nine browser checks of the API-hosted interface. That interface serves native modules; it is not a compiled Pages deployment. Public GitHub repository, Pages, Actions dispatch and release remain unverified.
