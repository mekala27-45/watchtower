# Operator procedure

Run deploy/Run-Local.ps1 to start the candidate. In a separate terminal run deploy/Verify-Local.ps1. These commands are concrete local verification helpers, not evidence that HTTP verification succeeded in this restricted session.

Run npm test for native tests, npm run evaluate for the frozen deterministic corpus, npm run eval:model for the actual-model availability gate and npm run reports to render evidence. The model command exits unsuccessfully when actual inference is unavailable and preserves every registered case. Never remove those rows to make a report pass.

The collect workflow contains a candidate UTC schedule and a disabled-by-default enable variable. It has not been dispatched or observed on a hosted runner. Its Postgres preflight intentionally refuses this local-only adapter. Do not enable the schedule until the direct TLS, secret route, persistent cache, account eligibility and dispatch checks have passed.

The Vercel Dockerfile requires a verified immutable Node image through NODE_IMAGE. Production mode refuses SQLite. Prepare-Deployment.ps1 checks the host book, image digest and target runtime adapter. It does not deploy incomplete local state or substitute another host.

Complete the target by restoring package and network access, implementing the pinned pg and eve adapters, verifying the exact CPU model artifact, and repeating the independent hosted checks. Enter required credentials only through platform secret settings. Then deploy the functional API, dispatch bounded collection, test Pages through the actual visible review controls and verify the remote release revision.

If a collection lease expires, acquire a new generation and retain the old attempt as history. If a publication response is lost, retry its original operation key and briefing digest. If dependencies changed before the effect committed, prepare and review a new revision. Do not delete receipts or rewrite prior evidence.
