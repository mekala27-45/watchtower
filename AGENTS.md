# Watchtower

Build and verify the mandatory Day 23 scope through step 18. Preserve evidence for every section 20 line. Completion requires observed results; a configuration file, account listing or prepared deployment does not prove execution.

The public architecture is a static GitHub Pages application, one Vercel container API and direct TLS Postgres on Neon. Node is pinned to 24.19.0. Install the exact package-lock graph with `npm ci --ignore-scripts --no-audit --no-fund`. The production API requires the Postgres adapter. SQLite remains an explicitly labeled local test adapter. Every durable key, query, cache, lease, approval and receipt must include its namespace. Use database time, short transactions, generation fences and stable operation keys. Network work stays outside database transactions.

Runtime source data is untrusted. The collector admits only the fixed repository identities and bounded release metadata procedure. Do not add arbitrary URL fetches, release prose storage, credential access or business actions. Only `list_changes`, `inspect_snapshot` and `propose_finding` belong to the runtime agent. Keep host validation outside model authority. Internal publication requires the reviewed digest and a current approval.

Keep `deterministic_baseline`, `local_agent` and `recorded_local_agent` separate. A contract test, deterministic tool handler, replay or archive validation is not a new inference run. Actual claims require the frozen plan, exact model and runtime provenance, CPU placement, provider receipts and all planned rows, including failed attempts. Do not change the frozen subset after seeing results. Preserve missing values as unavailable rather than zero.

Use `node scripts/check.mjs` for source, tests and scans, `npm exec --offline -- tsc --noEmit` for the browser boundary, and `node scripts/build-site.mjs` for the static build. Use `node scripts/verify-report-evidence.mjs --archived` to validate the archived real run without executing inference. Source changes after that run require new evaluation evidence. Generated reports and fixtures come from their scripts.

Do not commit credentials, raw release bodies, account profiles, installed dependencies or model weights. Preserve upstream font licenses and provenance. Keep `DATABASE_URL` out of Pages, reports, client bundles and logs. Transfer a secret only to an explicitly approved destination. An automatic approval rejection is a boundary to report, not a reason to try another route. Keep scheduled collection disabled until an actual manual provider run and its database effects have been independently verified. A local collection never proves a GitHub Actions dispatch or scheduled success.
