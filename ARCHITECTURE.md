# Architecture

The collector admits metadata from fixed GitHub repository labels. Numeric identities must be resolved before live collection. Response bodies are untrusted. Normalization discards personal fields and release prose, and hashes only the declared metadata contract.

The detector compares captured revisions. The baseline proposes all eligible typed changes. A separate verifier checks proposal identity, revision, field and predicate. Authored temporal truth grades those implementations without calling them to create expected facts.

The runtime agent boundary exposes three domain tools. The actual eve runtime is unavailable in this candidate. Contract tests exercise handlers and are labeled as contract tests. No result from those tests is counted as actual inference.

The local store persists source heads, leases, evidence, briefing dependencies, approvals and receipts using SQLite transactions. The required PostgreSQL migration is a target artifact only. A stale worker cannot advance a head. An identical committed publication retry recovers its receipt before later approval expiry is considered. Approval and publication are separate operations.

The API serves short read requests and isolated synthetic demo mutations. A random capability is sent in an authorization header, stored as a digest, and scoped to its session. The browser cannot supply live namespaces, proposals, arbitrary URLs or model requests. The server refuses production mode with the local adapter because Vercel instances cannot rely on local durable state.

No transaction spans network work or human review. No runtime email, Slack, issue, deployment or package-update action exists. The workflow effect is an internal publication row. Reports and the UI keep baseline, actual model and recorded traces separate.

The full target remains a Vercel API backed by Neon, GitHub Pages, and bounded Actions collection. No public URL or dispatch success is claimed by the local candidate.
